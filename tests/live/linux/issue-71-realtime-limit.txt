# #71: Linux, a session whose realtime priority limit is 0 is told at start,
# with the fix (join the pipewire group, or audio where there is none, then
# log in again), and the limit is logged.
# Needs: the Linux dev build, started from a shell where `ulimit -r` says 0
# (WSL's default; elsewhere: `prlimit --rtprio=0:0 bash`), and no dev app
# running (it starts its own, and quits it).
# Run:   ~/.cache/gigchain/build/linux-dev/gck-ctl run tests/live/linux/issue-71-realtime-limit.txt
# (The message is shown before the control listens, so `notices` has not
# seen it: the log's "Shown (warning)" line is what the player was shown.
# The message's own window is not in `shot`, the main window only.)
start
# (Its own launch: an app already running answers with no pid, and is left alone.)
expect pid > 0
# Only this launch's lines: the log keeps earlier launches'.
mark launch
wait "Realtime priority limit \(RLIMIT_RTPRIO\): 0" 15000 $mark
wait "Shown \(warning\): This session's realtime priority limit is 0, .*usermod -aG pipewire .*-aG audio if no pipewire group.*log in again" 5000 $mark
quit discard
