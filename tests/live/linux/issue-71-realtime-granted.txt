# #71, the other side: a session that grants realtime priority (a limit
# above 0) is not told anything; the limit is only logged.
# Needs: the Linux dev build, started from a shell where `ulimit -r` is above 0
# (`sudo prlimit --pid $$ --rtprio=95:95` raises it for that shell), and no
# dev app running (it starts its own, and quits it).
# Run:   ~/.cache/gigchain/build/linux-dev/gck-ctl run tests/live/linux/issue-71-realtime-granted.txt
start
# (Its own launch: an app already running answers with no pid, and is left alone.)
expect pid > 0
# Only this launch's lines: the log keeps earlier launches'.
mark launch
wait "Realtime priority limit \(RLIMIT_RTPRIO\): [1-9]" 15000 $mark
log $mark "Shown \(warning\): This session's realtime priority"
expect lines empty
quit discard
